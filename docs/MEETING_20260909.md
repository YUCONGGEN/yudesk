# 9 位临时会议与主持人屏幕共享（2026-09-09）

YuDesk 2.0.0 桌面端新增“会议”，Android `2.0.0-preview.6` 同步加入相同的临时会议协议。界面沿用现有紧凑浅色布局，并参考常见会议软件的“快速会议 / 加入会议”流程；没有复制第三方品牌、图标或页面资源。

## 使用方式

1. 主持人在“会议”中点击“发起会议”，YuDesk 向服务器申请一个独立的 9 位临时会议号。
2. 主持人复制会议号发给参与者。会议号以 `000 000 000` 分组显示，实际凭据仍是 9 位数字。
3. 参与者打开“会议”，输入会议号后直接加入，不需要主持人再次确认。桌面端可按能力选择听取主持电脑声音；Android 当前不支持系统声音，界面不提供无效开关。
4. 参与者只能观看主持人的桌面。鼠标、键盘、剪贴板写入和文件访问在协议层不授权，而不是只隐藏界面按钮。
5. 主持人点击“结束会议”后，当前参与者会断开，会议号立即失效。会议号最长有效两小时；主持设备离线、授权到期、被后台停止或服务器重启也会使目录失效。

当前每个会议最多一位参与者同时在线。参与者离开后，在会议仍有效且主持设备在线时可以重新加入。会议不会写入普通“最近设备”历史，也不会把服务器解析出的完整内部设备身份展示给参与者。

## 安全与传输

- 创建和结束会议必须由主持设备的 Ed25519 私钥签名；服务器校验身份、设备授权、在线管理通道和当前连接状态。
- 服务器只在内存维护短期会议目录，不写入会议号数据库或审计详情。服务器重启后所有旧会议号自然失效。
- 会议号查询使用证书校验的 TLS 通道，并复用服务端按来源限流；无效、过期、离线和已占用会议统一按不可用处理。
- 9 位会议号同时作为端到端会话内的临时认证凭据。即使解析到目标设备，错误或过期会议号仍会被被控端拒绝。
- 画面和可选系统声音继续通过 Agent ↔ Viewer 端到端加密通道传输；优先 P2P UDP 直连，打洞失败自动使用既有 TLS 中转。中转选择不改变参与者的仅观看权限。

9 位数字的便利性低于长随机口令，用户应把仍有效的会议号视为临时秘密，不要公开发布。当前通过短有效期、单参与者、在线状态约束、来源限流、设备身份签名和端到端二次校验共同降低风险。

## 验证结果与边界

- 全量 Go short 测试通过；Relay、审批、Agent、Viewer 和服务端会议路径通过竞态检测。
- Windows 发布 EXE 的双端隔离联调通过：创建 9 位会议号、号码与永久设备码分离、无需确认加入、读取真实桌面、仅观看、返回首页、主持人结束及号码失效均已验证；测试拦截输入，不操作真实鼠标键盘。
- 固定 860×600 窗口的会议页截图检查通过，没有横向/纵向页面滚动；全部确认提示使用现有自定义对话框，没有浏览器默认弹窗。
- Linux revision 7 安装包由 Ubuntu 22.04 目标环境构建；macOS revision 7 的 Intel/Apple Silicon 包由真实 Mac SDK 构建并完成 ad-hoc strict/deep 验签。尚未在 Linux/macOS 真实图形桌面上进行跨公网会议体验验收。
- Android preview.6 的四 ABI gomobile 绑定、Go 三轮竞态检查、Java 单元测试、SDK 35 编译、lint、APK 签名和 16KB ZIP 对齐通过。安卓可主持或参会，观看端自动进入横屏沉浸式全屏；当前没有连接 USB 真机，因此 MediaProjection 授权、厂商后台限制和两台真实设备公网会议仍需真机验收。
- 当前不包含多人摄像头/麦克风、聊天、录制、成员管理、主持权转移或多人屏幕共享；Android 也不支持系统声音。

部署批次、文件校验值和已知平台限制见 [当前发布状态](RELEASE_STATUS.md)。
