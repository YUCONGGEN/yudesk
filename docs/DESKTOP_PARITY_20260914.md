# 桌面同源发布说明（2026-09-14）

## 结论

Windows、Linux、macOS Intel 和 macOS Apple Silicon 的 YuDesk 桌面客户端均由
`cmd/yudesk` 同一入口和同一套 Go/UI 源码构建。不同系统安装包不会也不应具有相同
字节大小：Windows `.exe` 包含安装器外壳，Debian `.deb` 使用 xz 压缩，macOS
`.pkg` 包含 AppKit/WebKit 原生窗口组件、应用目录和签名封装，两种 Mac CPU 架构的
机器码也不同。

## 发布硬约束

- 四个桌面目标必须一次从同一个 40 位 Git 提交构建；
- 设置页显示该提交的 12 位构建号；
- Linux/macOS 打包时校验 Go 核心和原生窗口组件，安装包内记录完整提交号；
- 每个 `.deb`/`.pkg` 生成独立来源文件，记录核心、窗口组件和完成安装包的 SHA-256；
- 总发布脚本重新计算安装包 SHA-256，并与来源文件和桌面构建清单交叉核对；
- 缺少平台、来源文件、提交不一致、核心哈希不一致或安装包被替换时拒绝发布。

## 统一的桌面产品功能

三个桌面操作系统使用相同的主界面和功能入口：远程控制与观看、60 秒连接审批、
设备列表与在线检测、临时 PIN、剪贴板、授权目录文件传输、会议、端口映射、激活
授权、画质/网络设置、最小化、隐藏、全屏和关闭窗口后保持在线。连接协议、端到端
加密、P2P 优先与中转回退、帧编码、输入队列和会议信令也来自相同 Go 包。

操作系统安全机制不能伪装成相同：Windows 锁屏服务只适用于 Windows；macOS 的
屏幕录制和辅助功能、Linux 的桌面会话/输入工具必须由对应系统授权。此类差异属于
系统权限和驱动实现，不再允许演变成页面、协议或发布批次分叉。Android 使用独立
APK 和系统 MediaProjection/无障碍 API，不纳入“同一个桌面二进制来源”断言。
