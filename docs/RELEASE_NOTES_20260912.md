# YuDesk 2.0.0 延迟与启动稳定性更新（2026-09-12）

部署批次：`low-latency-restart-20260912.9`

## 本批次更新

- 远程画面的 ACK 在途窗口由固定时长改为最低 RTT 驱动：低 RTT 保持 2 帧，高 RTT 按带宽时延积在 2～8 帧间补足；排队造成的 RTT 增长不会扩大窗口，并继续触发画质与分辨率退让。
- 输入后的画面唤醒采用 100 ms 高频阶段和延续至 350 ms 的 60 Hz 尾段，兼顾直接鼠标反馈以及菜单、网页、动画稍后发生的重绘。
- 桌面与 Android 会议根据成员数、候选链路 RTT 和 WebRTC 可用上行带宽动态设置摄像头及共享屏幕码率，拥塞时优先保帧率与语音；Android 增加低延迟音频、快速抖动缓冲追赶、DSCP 和 CPU 过载检测。
- Windows 原生宿主在 Chromium 完成嵌入、样式确认及首帧合成前保持窗口隐藏并使用 DWM cloak，修复主进程结束后再次打开时短暂闪出独立浏览器窗口的问题。
- Windows 原生回归连续三轮、全量 Go 测试与静态检查、Viewer 竞态测试、Android 四 ABI/Java/lint/签名/16 KiB 对齐均通过；Linux 和两个 macOS 架构重新生成 revision 14 安装包。
- 2026-09-12 23:34（北京时间）完成原子部署。部署前两次确认活动会话为 0，发布后健康检查、数据库、固定 TLS 指纹、远控/网页/会议 TURN 的 TCP 与 UDP 监听及五个平台公网下载哈希均通过；Android Range 下载返回 206。

外网物理 RTT 无法由客户端消除。本轮针对排队、在途窗口欠填充、迟到重绘和会议拥塞预算优化，不把合成测试或服务器健康检查表述为所有运营商、设备和网络都能零延迟。

## 同日累计会议修复

- 修复会议原生全屏接口返回 `204 No Content` 时被客户端误判为失败的问题。旧版本会在原生全屏成功后再次叠加网页全屏，按 Esc 或结束会议只退出其中一层，导致无法取消全屏或主窗口保持放大；现在全屏模式有唯一状态，进入与退出严格成对，结束/离会会先恢复原窗口。
- macOS 原生窗口增加全屏转换状态协调：用户在进入动画尚未完成时退出会议，也会在动画完成后立即恢复原来的固定窗口。
- 会议新增真实声流显示。桌面从实际 WebRTC 远端音轨和本机麦克风 PCM 计算实时音量，Android 从麦克风样本及 WebRTC 接收统计计算音量；正在说话的成员显示绿色动态声流和高亮，未收到真实声音时不会伪造动画。
- 桌面远端会议声音继续由每条独立音频通道播放，并增加 Web Audio 能量监测；Android 启用低延迟语音采集、语音通信音频属性、扬声器播放状态同步和远端音频统计轮询。
- 通用本机 API 请求现在兼容 JSON 与无正文成功响应，避免最小化、全屏等原生操作已经成功却被页面当作异常再次执行。

- Windows、Linux 与 macOS：会议全屏保留明确退出入口，共享画面可点击聚焦；选择跟随后会自动切换到新的共享者。
- Android `2.0.0-preview.15 / 2000015`：同步提供横屏沉浸式共享聚焦、成员搜索、主持人管理和真实声流指示。
- 主持人可按姓名或成员标识模糊查找，通过桌面右键/操作按钮或 Android 成员菜单查看信息、转让主持人、移出成员。
- 服务器强制阻止被移出设备重新加入当前会议；会议结束后限制随房间一并清除。
- 共享按钮在系统选择、取消、拒绝、超时和主持权变化时可靠复位，不再永久变灰。
- 共享者姓名持续显示；主持权、成员状态和共享状态继续通过已认证信令同步，媒体仍使用 WebRTC DTLS-SRTP。
- 桌面远控与会议的“整屏显示”改为驱动原生宿主窗口进入当前显示器全屏；退出或按 Esc 后恢复原来的固定窗口位置和大小，不再只放大内部网页而留下边框。
- Windows 安装器增加本地诊断日志、顶层异常捕获和重复启动窗口恢复。安装完成后会等待正式 YuDesk 主界面真实可见再关闭，启动失败会留在安装页显示原因，不再表现为无提示闪退。

Windows 最终双进程回归实际验证了音频 RTP 持续增长、远端音轨播放、真实音量分析、Esc 退出全屏以及结束会议强制恢复窗口。Android 是预览版，已覆盖四 ABI 构建和自动化检查；不同厂商物理手机上的投屏权限、后台策略、声学效果和长时间温升仍需真机验收。macOS 双架构已在真实 Mac 上重新编译和验签，但外层 PKG 未做 Apple Developer ID 签名或公证。
