# P2P 优先与中转回退（2026-09-08，已部署）

本轮为桌面和 Android 共用 Go 核心增加原生 Pion WebRTC 数据通道：ICE/STUN 优先选择 UDP 直连，不能直连时继续使用原端到端加密 TCP 中转。不是改小页面显示数字；RTT 继续测量当前应用数据连接的真实请求/响应耗时。

## 连接顺序与权限

1. 连接现有中转，执行设备授权/归属检查和原 Ed25519/X25519 端到端握手。
2. 在加密连接中验证 PIN，或等待被控端明确同意（原 60 秒审批）。未通过认证不交换候选地址、不启动打洞。
3. 新端协商 `p2pV1`；旧端不支持时保持原协议。SDP、ICE 凭据、DTLS 指纹通过已认证的端到端加密信令交换。
4. 默认打洞预算 3 秒，信令结果确认额外预留 2 秒。双方确认同一个结果后才使用直连或回退；损坏的信令不能伪装成可复用中转连接。
5. 直连传输仍受 PIN/审批授予的观看、控制、文件权限限制。数据走可靠、有序、加密的 SCTP/DTLS/UDP 通道，继续承载现有画面分片、输入与文件协议。

直连成功后保留原加密中转连接作为授权生命线，约每 2 秒发送轻量心跳；失联判定有时间上限。后台断开、禁用、删除、服务端授权到期关闭原连接时，直连同步停止。当前在线/连接中的服务器统计继续有效，不会因为画面不经服务器而提前显示离线。

**初始打洞失败会自动回退中转。已经建立的直连若中途断网，当前会话安全结束；再次连接重新验证与选路。当前不宣称无缝迁移，也不在另一通道重放已执行的键鼠或部分文件数据。**

## 网络与服务端

- 默认发现地址：`stun:www.yucg.cn:8233`（UDP）。只使用自有服务器，不配置第三方 STUN 或 TURN。
- 原 `www.yucg.cn:8233` TCP 中转与 `http://www.yucg.cn:8235/` 页面不变。UDP 与 TCP 是独立的端口规则，开放 TCP 不能代替开放 UDP。
- 服务端新增 `-stun auto`（默认）：使用当前 TCP 中转的实际地址/端口提供绑定发现；`-stun ''` 禁用，显式地址可覆盖。UDP 启动失败不会阻止 TCP 中转启动。
- 用户确认后，已在实际路由器添加 UDP 8233 映射并从 Windows 开发机完成三次公网 STUN 绑定验证；原 TCP 映射未修改。UPnP 映射无租期到期，但路由器重启/重置后仍可能需要重建。
- 部署源配置已补齐 Docker UDP 8233 映射。macOS 的 UPnP 刷新脚本仅在显式设置 `YUDESK_STUN_PORT=8233` 时添加该 UDP 映射，原 TCP-only 调用不扩大范围。本次通过 UPnP 单独添加 UDP 8233，没有执行整组 TCP 刷新。
- STUN 只反馈请求的观察源地址，不中转画面、不支持 TURN 分配、不自动开放路由器端口。请求长度、回复体积、每源/IPv6 前缀及全局回复速率有界。
- 跨网络直连率取决于两端 NAT、IPv6、防火墙及 UDP 策略；对称 NAT、企业网络或运营商限制可能仍需中转。双方升级后才能启用新能力，旧服务器可继续承担透明信令/授权，中转回退仍兼容。

## 显示与诊断

桌面网络栏与 Android 远程工具栏显示“P2P 直连”或“中转”。桌面网络详情显示回退原因。RTT 是当前线路的应用层往返延迟，不是单程画面延迟。流量计数位于应用传输连接，不能当作含 UDP/DTLS/SCTP 链路头的网卡总字节数。

## 验证状态

- 桌面真实 Agent 处理链路：PIN 控制、空 PIN 审批仅观看、权限不升级、150,000 字节文件上传/下载与内容校验、直连不经中转发送文件载荷、关闭原中转后直连停止，通过。
- Windows 本机上述测试连续三轮通过；测试仅合成输入和临时文件，没有控制真实键鼠或锁屏。
- Android Go 核心控制端与被控端直连、PIN/空 PIN 审批、2048×1024 JPEG 完整性、关闭中转后会话停止，通过。
- 双 NAT 仿真：full-cone 与 port-restricted NAT 均通过 STUN 发现映射后直连，检查所选候选确实跨越两个 NAT；双 symmetric NAT 双方一致回退中转。两方向载荷均校验完整，不把仿真当作真实运营商 NAT 验收。
- 包级验证覆盖无 UDP、超时、一方不支持、旧端缓冲消息保留、伪造/不一致协商失败关闭、短读保留完整数据、有界背压、deadline 更新、并发退出、管理链路黑洞和上下文取消。
- STUN 在 Linux race 与真实 Windows 完整测试通过，含多地址回复源、IPv6、超大报文、未知属性/CRC/长度、限流、启动失败回滚及取消；10 秒 fuzz 218,051 次通过。
- 根模块全量 `go test -race ./...`、桌面 Agent/Viewer 与 Android 核心竞态回归通过。
- 真实本机 broker 的 TCP/TLS 连接中完成加密认证后切换 P2P：双向多条完整有序载荷（最大 2MiB）、管理员断开、任一服务端管理连接关闭、在线状态清理和一次性 STOP 均通过。自然授权到期另外使用临时数据库设定约 5 秒期限，两轮竞态测试均验证直连终止、再次连接被拒；没有修改真实授权最短时长。
- Windows 完整 peerpath 测试通过，含双 NAT 仿真、旧协议、背压/短读/并发退出、超过建连预算后会话仍存活，以及管理连接静默黑洞的超时终止。
- 模拟线路对照：本机 TLS broker 每方向出站人为增加 25ms，64 字节应用 ping 预热 2 次后测 8 次；中转均值约 51.38ms，P2P 约 0.30ms。仅证明直连绕过人为增加的中转路径，不代表真实公网 RTT；竞态检查增加开销的三轮均值分别约 51.48–51.93ms 和 1.30–2.55ms。
