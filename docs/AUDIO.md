# 按需系统声音

## 使用

两台电脑都更新到当前合并版 YuDesk。连接后点击顶部喇叭开启，再点关闭。连接前未勾选声音，也可以在会话中开启；进入页面不自动播放，遵守浏览器用户手势要求。顶部盾牌打开“连接与声音”，显示真实会话权限、声音来源与状态，可调本机播放音量，不修改对方系统音量。

- Windows：WASAPI 默认播放设备回环，不是麦克风。声卡初始化失败、拔出或流结束有明确提示，可修复设备后重新开启。
- Linux：需要 PulseAudio 的 `parec`/`pactl`，或提供兼容接口的声音服务；使用默认输出的 monitor。
- macOS：本版本尚未实现系统声音采集，被控端为 macOS 时显示不可用；不能将跨平台编译通过当作声音已支持。
- 只有系统播放混音，不包含麦克风、摄像头、远程更换扬声器或远程静音扬声器。不提供隐私屏、虚拟屏、关闭显示器开关。

## 修复与边界

新增协商能力 `audioOnDemand`：网页监听音频时启动采集，退出/关闭时停止。旧对端仍按旧方式协商，不应声称停止旧对端的采集；建议两端同时更新。

采集与网络发送分离，采集不等待拥塞写入；Agent 和 Viewer 各最多保留 3 个 20ms 小包。浏览器对 TCP 合并读只保留最新 80ms，排程目标窗口最多约 140ms；重同步先取消旧排程，避免重叠。此值仅为各缓冲上限，不是端到端延迟承诺。快速关闭/重开采用独立播放实例；旧请求失败不能取消新实例。服务端串行化音频监听及清理，防止旧请求的 stop 停掉新采集。

目前传输格式为 48kHz、双声道、16 位 PCM，持续声音约 1.536 Mbps（未计协议开销），尚未实现 Opus/WebRTC 音频。网络很慢时可能丢弃旧音频产生短暂断续；不会为了连续播放无限积累延迟。受保护内容、设备独占模式和系统音频策略可能限制回环采集。

## 验证

- Go 竞态测试：按需启动/停止、重复启动拒绝、停止后资源释放、重启、采集故障、慢写不阻塞采集；Viewer 无监听不缓存、队列/单包有界、停止先于下一次启动。
- Node：小端有符号双声道和任意字节分片、突发积压丢弃/旧源取消、输出暂停、音量边界、旧请求迟到、EOF 后重开。
- Windows 原生 WASAPI：短测试音实际输出与回环采集，检查非静音样本，不把静音包当成声音成功。
- Windows 本机端到端：临时设备及本机中转，通过真实加密 Agent/Viewer、HTTP 音频流和 Chromium Web Audio 接收非零 PCM，开关/快速切换/音量和桌面同时运行验证。浏览器无界面，不注入真实鼠标键盘，不采集麦克风，不保存或上传音频。
- 非两台异地机器听感测试，不证明所有声卡/音响、macOS/Linux 声音或长时间弱网表现已通过。

实现依据：[Microsoft WASAPI 回环录音](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)、[W3C Web Audio](https://www.w3.org/TR/webaudio/)。
