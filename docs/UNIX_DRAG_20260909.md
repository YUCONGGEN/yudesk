## macOS：一致性修复、双架构构建与离屏验收

首轮仅审查源码，未修改 macOS。用户随后明确授权评估 mousedown 一致性修复，并允许 SSH 到 `yu@www.yucg.cn:2222`，仅在 `/Users/yu/bin/yudesk/staging` 构建，禁止开窗和部署。以下是该后续授权范围内的结果。

审查依据：`ShellWindow.sendEvent` 在 `super.sendEvent` 前保存 leftMouseDown，leftMouseUp 清除；消息处理检查主 frame、同源、最近按下小于 0.5s、`NSEvent.pressedMouseButtons & 1`，消费 `lastPress` 后调用 `performDrag(with:)`。native 授权本来就绑定 mouse down，而非任意 pointer 激活。

鼠标每次按键产生 mousedown；pointerdown 受指针按键状态转换约束，二者语义不同。`isPrimary` 是 PointerEvent 的属性。标准依据：[W3C Pointer Events — chorded button interactions](https://www.w3.org/TR/pointerevents3/#chorded-button-interactions)、[the primary pointer](https://www.w3.org/TR/pointerevents3/#the-primary-pointer)。结合 Linux 已实测的“释放被原生拖动接管后缺少下一次 pointerdown、仍有 mousedown”，本次选择让 Mac 的 JS 桥与其既有 leftMouseDown 授权对应。这是有依据的预防性一致性修复，不是宣称已在 Mac 复现同一故障。

`native/macos/Window.swift` 仅修改注入脚本两处：`pointerdown` → `mousedown`，以及删除 `!e.isPrimary`。只改事件名而保留后者会因 MouseEvent 没有此属性而拒绝全部鼠标拖动。可信事件、左键、拖动区域、控件排除均保留；native 保存/释放事件、同源、主 frame、时间限制及单次消费不变。没有修改 launcher、`build.sh`、离屏探针、共享 JS 或 Go。
