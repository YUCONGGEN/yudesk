# YuDesk 多人音视频会议（2026-09-11）

## 交付内容

`multiparty-conference-20260911.1` 将原来的“一位主持人共享、一位参与者观看”升级为最多 **8 人**的小型音视频会议；`conference-turn-20260911.5` 修复 Windows 与 Android 跨公网入会后互相无声的问题，`meeting-management-20260912.7` 完善主持人管理和共享聚焦，`meeting-fullscreen-audio-20260912.8` 修复叠加全屏并加入真实声流显示。Windows、Linux、macOS 和 Android 使用同一套房间、成员和 WebRTC 信令协议。

- 发起人与参与者均需填写 1～32 个字符的姓名；
- 发起人创建独立的 9 位会议号，并作为第一位主持人进入会议；
- 参与者输入会议号后直接入会，不需要主持人二次确认；
- 参会者可独立开关麦克风和摄像头；
- 参会者可独立关闭或恢复远端会议声音；
- 主持人可共享屏幕、按姓名或成员标识模糊查找成员，并通过右键或操作菜单查看信息、移出成员、转交主持人和结束会议；
- 被移出的设备在本次会议结束前不能再次加入，限制由服务器执行，不依赖客户端自觉退出；
- 共享者姓名持续显示；参会者可点击共享画面聚焦全屏，之后共享者变化时会自动跟随切换；
- 主持人可在本机录制当前会议画面；桌面保存 WebM，Android 保存本地视频文件；
- 桌面和 Android 会议均支持横屏全屏；
- 成员离开、网络断开或主持权变化会即时更新成员列表和媒体状态。

会议页面采用原创的浅色留白、灰白层级、蓝色主操作和紧凑工具栏。视觉语言参考 `E:\welink`，没有修改该目录，也没有复制第三方品牌、图标、代码或页面资源。

## 传输架构

```text
参会者 ── 设备签名 + 固定证书 TLS ── YuDesk Relay ── 会议成员
                     只传房间状态、SDP、ICE

参会者 ═══ WebRTC / ICE / DTLS-SRTP：P2P 优先，TURN 回退 ═══ 参会者
             TURN 仅转发端到端加密后的媒体数据包
```

每个参会者与房间内其他参会者建立 WebRTC 连接，使用 `max-bundle`、ICE 和 DTLS-SRTP。即使麦克风和摄像头均关闭，也会创建只承载会话的 data channel，使 SDP 保持有效并允许入会后再打开媒体。客户端先尝试 P2P；3 秒内没有可用媒体路径时加入服务器下发的短期 TURN 凭据并重启 ICE。TURN 使用 UDP/TCP `8254` 与 UDP `20200-20295`，只看到加密数据包，不能读取麦克风、摄像头或共享画面。

会议号不是主持人凭据。初始主持人必须使用会议所有设备的 Ed25519 私钥完成随机挑战签名；所有参会设备都必须在线、已激活并通过设备身份校验。同一设备不能同时重复加入同一会议。会议最长有效两小时，主持人结束、授权失效、服务器重启或房间清理后失效。

## 稳定性修复

本批次在真实 Windows 与 Android 联调中发现并修复三项会造成“卡在连接中”或成员误掉线的问题：

1. TLS 可能把 `OK` 与第一条 `welcome` 合并到同一记录。旧代码认证后丢弃缓冲区中的 `welcome`，客户端会一直等到超时；现在连接保留原缓冲读取器，并有合并报文回归测试。
2. 麦克风和摄像头均关闭时，浏览器生成没有 BUNDLE 组的空 SDP，与 `max-bundle` 冲突；现在所有连接先建立轻量 data channel，用户仍可在入会后按需打开麦克风或摄像头。
3. 成员离开后，网络中可能还有发给该成员的迟到 ICE。旧服务器把它当成协议错误并断开发送者；现在只忽略已离开目标的陈旧信令，并用三人加入、离开、迟到 ICE、继续心跳的回归测试覆盖。
4. 桌面端过去把远端声音依附在参会者视频标签上，自动播放或多音轨切换失败时会表现为“音轨在线但扬声器无声”。现在每条远端麦克风和系统声音都使用独立音频元素播放；Windows 独立窗口允许会议媒体自动播放，三种桌面界面都提供“关闭声音 / 播放声音”按钮，失败时显示可操作的中文提示。
5. 会议新增紧凑的“声音设备”面板，显示本机麦克风电平、所有可用扬声器和当前播放路数；用户可切换输出端点并播放短测试音。选择失效设备时自动回退系统默认扬声器。
6. 桌面共享原先明确使用 `audio:false`。现在会请求可选系统音频，把麦克风与系统声音作为不同 WebRTC 音轨发送，并在接收端分别播放。操作系统没有提供音轨时会提示用户在共享选择窗口勾选“共享音频”。
7. 连续添加画面和系统声音时，旧协商函数会在首个 SDP offer 尚未完成时丢弃第二次协商。现在媒体变更先批量完成再发 offer，并保留待协商状态，在连接恢复 `stable` 后自动继续；快速停止共享也不会留下失效发送轨。
8. Android 会议现在显式创建 `JavaAudioDeviceModule`，配置硬件回声消除、降噪、录音错误回调和通话扬声器路由；双方即使一开始没有开启摄像头，也会预先建立可接收音频/视频的 transceiver。
9. TURN 凭据只通过已认证的会议信令连接发放，绑定房间和成员并在两小时后失效；成员离会后服务端立即撤销该成员的中转分配，并限制分配数量、速率和可访问地址。
10. 共享按钮增加“系统选择中”状态和超时/取消/失败复位，避免取消系统共享窗口后按钮永久变灰；主持权在选择过程中改变时会安全停止刚取得的采集轨道。
11. 桌面会议全屏改为驱动原生宿主窗口占满当前显示器，并只显示会议容器、保留退出入口；退出后精确恢复固定窗口。聚焦共享画面后仍可一键返回宫格。Android 使用横屏沉浸式布局，返回键优先退出共享聚焦或收起成员面板。
12. 原生全屏接口的无正文成功响应不再被误判为失败，避免原生层和网页层重复进入全屏。全屏按钮、Esc、离会和结束会议使用同一套状态机，每次进入都有对应恢复；macOS 在全屏过渡动画中收到退出请求也会继续完成恢复。
13. 声流标识来自真实媒体能量：桌面分析本机麦克风和每条 WebRTC 远端音轨，Android 分析本机 PCM 与远端 `inbound-rtp` 音频统计。只有达到声音阈值的成员才显示动态绿色声流，不以定时动画伪装声音。

## 录制与权限

录制只在主持人的本地设备执行，不上传服务器。桌面端把当前会议宫格与可获取的会议音轨合成为 WebM；浏览器/系统组件不支持 MediaRecorder 时会明确提示。Android 录制当前视频/屏幕画面，暂不录制会议音频或系统声音。所有摄像头、麦克风和 Android MediaProjection 权限均由操作系统授权窗口控制，YuDesk 不绕过系统权限。

## 当前边界

- 会议媒体仍是 **P2P 优先的全互联 mesh**，直连失败会自动回退 TURN，但没有 SFU。完全封锁 UDP 与非标准 TCP 端口的网络仍可能阻止媒体建立；会议不应宣传为大型会议系统。
- 每增加一名成员，每台设备都要增加上行/下行和编解码负载。产品上限为 8 人，但高清视频的实际可用人数取决于设备性能和上行带宽。
- Android 本地录制暂不含会议/系统音频；Android 屏幕共享也不采集其他应用的内部系统声音。
- Android 已做 API 26 模拟器与公网跨端联调，但没有覆盖所有厂商物理手机；MediaProjection、摄像头切换、后台策略和长时间温升仍需真机验收。
- macOS 安装包尚未 Developer ID 签名或公证；Linux Wayland、macOS 图形真机会议仍需对应真实桌面验收。

以上限制不会伪装为已完成能力。若后续目标是几十人会议或进一步降低多人上行，应增加 SFU，而不是继续扩大 mesh。
