# 桌面窗口拖动修复（2026-09-09）

针对去掉系统标题栏后“界面无法拖动”，覆盖统一主界面、远程界面及连接/返回过渡页。Android 没有桌面窗口拖动操作，本轮保持原 preview.5 APK；iOS 与原生鸿蒙继续暂停。

## 原因与修复

- Windows 原来通过页面按下事件发 HTTP 请求，再异步发送移动消息。真实快速拖动时，处理请求时鼠标可能已松开，或已经到达终点，不能把“成功发送命令”当作窗口发生了位移。内嵌浏览器的鼠标捕获、焦点与子窗口层级也影响重复拖动。
- 页面提前上报顶部非交互区域，Windows 自己的窗口线程通过原生子窗口和 `WM_PARENTNOTIFY` 接收按下事件，保留按下坐标，进入系统移动循环。原生按下使用消息队列的按键状态；HTTP 后备使用实时按键状态，拒绝释放后到达的请求。没有全局鼠标钩子，没有注入或子类化其他进程。
- 拖动区域排除按钮、表单、链接、输入框等交互元素；弹窗、全屏、离页时清空。布局上报限 8KB、16 个区域及顶部 100 CSS 像素；只有本机令牌保护的 POST 可修改，尺寸不匹配或租约失效则不使用。相同几何不反复重设子窗口位置。
- 拖动操作只作用于 YuDesk 本地窗口，不进入远程鼠标队列；释放其他应用的捕获被拒绝。连接过渡页补齐了完整顶部拖动区域。
- Linux 真实复现 WebKit 在一次原生拖动后缺少下一次 `pointerdown`，但仍有可信 `mousedown`。原生桥改用后者，保留真实输入、左键、同源、时间和控件排除约束。macOS 的桥也与既有 `leftMouseDown` 校验保持一致。详见 [Unix 证据及限制](UNIX_DRAG_20260909.md)。

## 验证与限制

Windows 通过明确授权，仅使用独立本地测试窗口：没有设备身份、真实远程连接、系统服务、真实远程输入。测试使用真实页面顶部布局和实际宿主窗口；鼠标操作由计算机使用工具执行，位移由窗口自身报告的 Win32 坐标核对，不以模拟消息成功或程序直接设置坐标作为成功判据。

最终实测：主界面两次 `(13,13) → (103,73) → (193,133)`；远程页两次 `(193,133) → (283,193) → (373,253)`；用户随后自行移动测试窗口，再测试过渡页两次 `(619,185) → (709,245) → (799,305)`。六次均与指定鼠标位移 `(90,60)` 相符，窗口大小不变。工具截图接口不受此 Windows 环境支持，因此使用可访问性树/测试窗口标题观察，不宣称完成截图验收。

全量 Go 测试与 vet、Windows vet、核心 race、拖动区域边界/鼠标捕获所有权/松开竞态测试通过。原生窗口导航、最小化恢复、大小调整、最大化恢复、隐藏复用和标题栏修复通过。一次与大量浏览器回归同时执行时触发了旧浏览器清理的 3 秒等待超时；单独重测及随后连续三轮完整窗口生命周期测试通过。保留该异常记录，尚不能据此保证所有电脑高负载下的清理时限。

共享窗口/弹窗/区域更新测试最终 42/42 通过，另有 23 项输入、帧、文件、音频、兼容及在线查询测试通过。动态插入控件时的旧请求竞态在测试内按构造请求的布局版本区分，没有通过跳过错误区域来放宽断言；在已有请求尚未完成的条件下，新布局实测于 448–1232ms 恢复，截止 1800ms。最终 Windows EXE 的统一端连接、设备列表、返回首页、仅观看与 60 秒审批联调通过。

Linux 在 Ubuntu 22.04 / 24.04 的独立 X11 环境完成实际输入拖动和既有回归；macOS arm64/amd64 构建、URL 自检及离屏 WebKit 检查通过，但没有 macOS 真机拖动验收。Linux 原生 Wayland、触控/笔、多显示器不同缩放和长期高负载没有完整实测。

## 更新方式

产品版本保持 2.0.0；本轮桌面安装包批次为 `drag-20260909.1`，Unix 安装包 revision 5。是否已上线及最终校验值以 [发布状态](RELEASE_STATUS.md) 为准。

先完全退出旧 YuDesk，再安装官网对应平台的新包。仅关闭/隐藏界面或重新打开旧程序，不能替换进程内已经加载的旧代码。原设备身份、授权和设备列表保留。
